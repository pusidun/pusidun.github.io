# Vibe Watching

把视频中的信息初步加工为便于人工学习的知识：读者先理解问题、概念关系和关键推导，再按明确时间点回到原讲解验证、实验和思考。输出是学习入口，不是逐字稿换行，也不是脱离视频的百科文章。

## 范围与本项目约定

- 先识别本次请求是课程目录、单讲笔记还是完整系列。B 站一个 BV 的分 P 与所属合集中的其他 BV 是两层范围；不要因为能取得合集就自动处理整个合集。
- 文章写入 `src/content/blog/`，中文正文保留原文风格，标签含 `vibe watching`。阅读 `src/content.config.ts` 和近期笔记了解当前 schema；标题、摘要包含核心概念名称，因为本仓库不搜索正文。
- 新增或调整文章后维护 `2026-09-12-writing-roadmap.md` 的阅读路径。系列内部提供目录与相邻篇链接，不预设必须写几篇，不把尚未生成的文章列为已完成。
- 不因写完笔记自动 commit、push 或发布。根据用户本次授权执行；提交格式遵循项目 `AGENTS.md`。

## 先建立可核对的来源

链接只是访问入口，来源身份必须能脱离链接阅读。记录原讲者/作者、完整课程名、机构或主办方（有依据时）、课程版本或年份（可核实时）、讲次标题、使用的平台版本及核对日期。区分原讲者与上传者，官方回放账号也不要误标成第三方转载。

从课程主页、原讲者发布页、片头或课件署名核对作者；不能用上传账号名、ASR 猜测的人名或人脸识别替代。未查明时写“讲者暂未核实”，保留完整课名与可验证线索，不填猜测值。课程年代不能直接取转载日期。

保存目录清单：每讲的序号、标题、BV/CID 或其他来源标识、时长、链接和处理状态。完整课名与讲题能用于检索；BV/CID 只能定位某个平台版本。清除 `vd_source`、`trackid`、`spm_id_from` 等跟踪参数。涉及与文章无关的作者个人联系方式或雇主信息，不追加收集或发布。

## 获取内容与时间证据

按需阅读 [references/workflow.md](references/workflow.md)，获取转录、课件和中断恢复的具体做法。

1. 优先取得可用字幕，同时检查它覆盖的语言、分集和时长；没有可用字幕再下载音轨、本地转录。使用已有 `bilibili-video-reader` 能力时先读其说明；也可以使用可用的字幕接口、下载器、ffmpeg 和本地 ASR，不依赖某台电脑的绝对路径或特定模型。
2. 转录同时保留带时间轴的 SRT/VTT 与可读文本，记录源视频、分集、时长和工具配置。仅有纯文本不能反推出精确时间。阅读完整转录，检查尾部是否缺失、长段是否空白、术语或重复幻觉是否异常。
3. 按内容密度抽样课件，在概念转折、代码修改、图示、结论处加密检查。采样间隔不是知识点时间戳；需要回看具体字幕/画面，确认该时间确实出现目标内容。
4. 为关键证据建立记录：讲次、起止时间、屏幕标题/关键词、讲者的论点、原例与变更步骤、疑点。文字转录未覆盖的板书、PPT 和代码以画面补齐；图像不清楚时标记缺口。

可用 [scripts/index_srt.py](scripts/index_srt.py) 把 SRT 整理为带原始时间、秒数及 B 站跳转链接的 JSON。它仅转换坐标，不验证语义，也不修复 ASR。按关键词搜索后仍要阅读上下文并核对画面。

## 从 info 到 knowledge

完成对应内容的阅读后再决定文章分组。把各讲做成覆盖矩阵，沿着问题、先修依赖、共同案例或变化方向归并；保留“哪篇覆盖哪讲、哪些内容暂缺”的映射。

每个重要主题应让读者理解以下关系，按内容选择自然的段落结构，不必机械凑齐小标题：

- **问题与先修**：原来想完成什么，为什么旧办法不够，读者需要先理解什么。
- **概念与机制**：概念的职责、内部过程、与相邻概念的差别；术语第一次出现时说明含义。
- **推导与案例**：保留课堂初版、需求变化、中间尝试与最终取舍，说明因果而非只列定义。
- **适用边界**：假设、失败情形、资源与性能代价、什么时候不值得使用。
- **连接与迁移**：联系本仓库已有文章；借助模型知识补充对照、反例、现代实践和实验，让读者能举一反三。

明确区分“课程观点/演示”“整理者解释”“现代补充或修正”“尚待确认”。模型知识用于提出联系和解释，不当作视频证据。版本敏感或有争议的技术结论查阅标准、官方文档或论文；尤其不要把旧课中的编译器行为、历史性能判断提升为语言保证。

完整代码标明语言版本、依赖及教学边界，实际编译/运行有意义的断言；结构片段明确省略内容。C++ 示例关注所有权、析构、复制、异常和并发契约，但不为无关主题强行加入一套通用检查表。

## 让读者能回到视频

每篇提供一份精简的重点回看表，列出“讲次 + 可见起止时间 + 画面/讨论线索 + 值得回看的原因”。核心推导可在对应正文就地附时间点。不要给每句话贴一个时间，也不要只提供一条整集链接。

- B 站跳转通常用 `https://www.bilibili.com/video/BV…/?p=N&t=整数秒数`。先确认当前播放入口支持跳转；文字中仍显示 `P3 · 12:40–15:10`，不把定位完全寄托在播放器参数上。
- 时间属于所核对的具体视频版本；另一个上传版本可能有剪辑、前导广告或合并分集。来源卡中说明版本，表中保留讲题及画面关键词，方便链接失效后重新查找。
- 精确到秒不代表证据精确。粗采样只支持近似时间时标“约”，无时间轴或无法核对时明确缺失，不编造时间以完成表格。

适量加入思考题与扩展点：例如预测执行结果、改变一个假设、找反例、比较两种方案、设计一个最小实验。让问题有明确检验方式或提示，区分课程内可解的问题与需要额外阅读的扩展；不要用泛泛的“你怎么看”凑数。完整参考答案可以折叠，避免遮住读者自己的推理。

具体版式参考 [references/post-template.md](references/post-template.md)，按主题裁剪。

## 完成与交付

- 核对目录范围、转录覆盖、关键画面、原讲者/课程归属，以及文章到讲次/时间的映射。未覆盖的片段如实说明，不声称看完未读取的内容。
- 检查站内链接、来源信息、标签、摘要、代码与时间跳转；运行 `npm run build`。按内容和布局改动选择验证，不为纯文本修改重复扩大测试范围。
- 原始媒体、字幕和转录中间件不写入公开文章或 `public/`。完成来源复核后清理临时音视频；转录与证据记录是否保留遵循用户要求和所用工具约定。需要后续人工校订时可保留在确认被 Git 忽略、不会部署的 `private/vibe-watching/` 中，交付前说明位置与校订状态。
- 交付说明已处理范围、生成文章、尚缺证据与已做验证。明确这是 AI 初加工的学习笔记，让后续人工学习有入口、有证据、有可检验的问题。
