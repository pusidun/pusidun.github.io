这里的文章写于不同阶段：有语言特性的小实验，有源码阅读，有系统编程笔记，也有借助 AI 整理的课程与访谈。按发布日期翻阅，不一定容易看出它们之间的联系。这篇导读把已有内容按学习问题重新串起来，方便从当前需要解决的问题进入。

不必先读完所有基础，再接触感兴趣的主题。先选择一条路线，遇到具体概念再回到相关基础，通常更容易形成自己的问题。每组下面的顺序是阅读建议，不是完成时间表，也不代表读完就掌握了整个领域。

## 先选一个想回答的问题

| 你现在关心什么 | 可以从哪里开始 | 遇到困难时回看什么 |
| --- | --- | --- |
| AI 能写代码以后，我还需要判断什么 | 生成式软件工程与 Clean Code 访谈 | 设计原则、版本管理和可验证的代码例子 |
| 代码一加需求就到处修改，怎么拆分 | C++ 设计模式系列 | 类、虚函数、组合和资源所有权 |
| 想从会写代码走向读懂库的实现 | 语言与内存，再读 Redis、muduo | 指针、模板、对象生命周期与并发基础 |

## 一、AI 辅助开发：先理解责任，再组织任务和版本

这一组适合已经写过一些程序、想把 AI 引入开发流程的读者。先修不在于掌握复杂模型数学，而在于能够区分“生成了一段代码”和“完成了一个可以验证的需求”。

建议先读蒋炎岩《生成式软件工程》的前三讲，再用 Uncle Bob 的访谈换一个角度检查自己的判断：

1. [第一讲：欢迎来到未来](/blog/2026-09-08-generative-software-engineering-welcome-notes/)从模型与 Agent 的能力、意图和规格的差距，以及课堂实验出发，讨论生成成本降低后，工程工作为什么仍然存在。
2. [第二讲：提示词、上下文与探索的组织方式](/blog/2026-09-08-generative-software-engineering-prompt-notes/)把问题推进到任务执行：怎样说明完成标准，怎样提供上下文，怎样获得反馈，什么时候需要并行探索。
3. [第三讲：软件仓库管理](/blog/2026-09-09-generative-software-engineering-repository-notes/)讨论成果怎样保存和汇合。从 Git 的快照、暂存区、提交与合并，走到仓库约定和多个 Agent 协作的问题。官方讲义的延伸讨论与视频内容在文中分别说明。
4. [Uncle Bob 访谈：AI 写代码之后，工程师关注什么](/blog/2026-09-08-uncle-bob-ai-agents-clean-code-notes/)整理 Kent C. Dodds 与 Robert C. Martin 的 *Architecture, AI agents, and product empathy with Robert C. Martin*，补上代码审查、架构、质量反馈与学习过程的视角。这期节目与 *AI Agents for Clean Code* 培训相关，但不是培训录像。

读这一组时，可以始终带着一个小任务：写下需求、列出验收条件，让 AI 实现，再检查结果与提交。目标是能解释哪里需要人作判断，以及判断依据是什么。这里提出的是阅读练习，不是文章已经提供的统一实验项目。

如果发现自己很难评价一段代码的结构，可以接着走设计模式路线；如果关注工具会读取什么、能执行什么，则转到最后的 Agent 安全路线。

## 二、软件设计：从变化出发，逐步找到合适的边界

这组内容使用 C++，适合已经了解类、继承、虚函数和基本对象生命周期的读者。设计原则并不只适用于 C++，但读具体代码时，需要能区分接口调用、对象创建和资源释放。

[早期的《设计模式（一）：设计原则》](/blog/2020-08-23-design-pattern-1/)可以作为简短概念索引，了解稳定与变化、SOLID 和依赖方向。更完整的推导放在新整理的八篇系列中：

| 阅读顺序 | 这一篇想解决的问题 |
| --- | --- |
| [一：从变化出发，而不是从类图出发](/blog/2026-09-12-cpp-design-patterns-01-foundations/) | 用绘图程序的演化理解抽象，建立全课目录和模式选择方法 |
| [二：流程、算法、状态与通知](/blog/2026-09-12-cpp-design-patterns-02-collaboration/) | 分辨固定流程的钩子、可替换算法、状态迁移与事件订阅 |
| [三：把创建对象的变化放到合适的位置](/blog/2026-09-12-cpp-design-patterns-03-creation/) | 类型由谁选择，产品怎样成套创建，何时复制、何时分步构造 |

读法可以很具体：先理解课堂的朴素方案，再想一次新需求会改到哪里，最后对照重构后的结构。文中的完整示例可以作为实验起点，但“示意片段”只用于说明关系，不应当作独立程序运行。也可以故意改一个条件，例如让命令执行失败、让观察者提前销毁，检查原先的契约哪里不够。

## 三、语言与内存：为源码阅读补上具体机制

这一组不是完整语言入门，而是围绕几个容易在源码中遇到的问题展开。建议已经能写简单 C++ 或 Java 程序以后，再按需要进入。

### C++ 与 C：参数、所有权和数据表示

- [C++17 折叠表达式](/blog/2020-09-03-fold-expressions/)从变长参数求和进入，讨论怎样用折叠表达式组织参数包操作。适合作为阅读模板代码时的专项补充，先了解函数模板和参数包会更顺畅。
- [GCC 5.4.0 `shared_ptr` 引用计数源码阅读](/blog/2020-07-15-sharedptr-cnt/)沿具体标准库版本分析引用计数结构。可以接在设计模式第六篇之后，继续追问共享所有权在实现层面怎样表达；文中的实现细节具有版本范围。
- [Redis 源码阅读：简单动态字符串 SDS](/blog/2019-12-14-redis01sds/)从 C 字符串的表示进入长度、容量、分配和拼接，比较文中涉及的 Redis 版本。适合练习“数据结构为什么长这样”，先熟悉指针、数组和内存分配。

这三篇可以形成一个小循环：先读语言表达方式，再看对象怎样管理资源，最后看库怎样为自己的需求选择数据表示。不要把某一版库的内部类名或内存布局当成语言标准的要求。

### Java：时间模型与内存回收

[Java 中时间处理](/blog/2020-03-09-java-time/)按旧时间 API 与 `java.time` 梳理日期、时区、格式化和转换，适合遇到具体时间处理问题时查阅。

[《深入理解 Java 虚拟机》第三章：垃圾收集器与内存分配策略](/blog/2021-04-12-深入理解java虚拟机ch3/)从哪些内存需要回收、什么时候回收、怎样回收三个问题进入引用、可达性和收集算法。可以与 C++ 引用计数阅读对照，但不要把两种语言的生命周期模型简单等同。

旧笔记保留了写作时的版本与术语背景。复现 API、编译器行为或垃圾收集机制时，应先确认所用版本，再对照当前官方文档和实际结果。

## 四、Linux 与网络：从一次读写走向事件驱动程序

这条路线适合想理解服务器底层执行过程的读者。先修包括 C/C++ 基本语法、指针与缓冲区；读到多线程部分时，还需要补上共享状态和同步的概念。

[Ubuntu 常见服务搭建记录](/blog/2018-04-05-ubuntu-service/)记录了 SSH、Samba 与编辑器配置，正文使用 Ubuntu 16.04 环境。它可以帮助理解早期实验环境怎样准备，但属于历史配置记录，不是当前发行版的通用部署指南。

网络编程正文建议按以下顺序读：

1. [《The Linux Programming Interface》File I/O](/blog/2021-04-09-linux-programming-interface-fio/)整理 Michael Kerrisk 书中的文件 I/O 内容，从 `open`、`read`、`write`、`close` 认识文件描述符与系统调用。
2. [socket 编程（一）](/blog/2021-05-18-linux-socket1/)进入地址结构、字节序、连接建立和通信例子。目标是能沿一次连接说明客户端和服务端分别调用了什么。
3. [socket 编程（二）](/blog/2021-05-19-linux-socket2/)继续讨论字节流上的应用消息边界、收发接口、地址查询和子进程回收。可以带着“接收到的字节怎样还原成一条消息”这个问题阅读。
4. [select、poll 与 epoll](/blog/2021-05-20-linux-selectpollepoll/)讨论同时等待多个描述符的方法及例子。先理解前面的连接与读写，再看就绪通知，能避免只记住几个 API 名称。

本站 muduo 笔记以 v2.0.2 为阅读背景，适合完成上述基础后挑选具体模块分析：

## 五、Agent 终端安全：把“可以做什么”落到执行边界

这组文章关注 Agent 获得文件、进程、网络和插件能力以后，怎样定义与实施权限。建议先了解基本的 Agent 工具调用流程，以及操作系统里的进程、用户、文件和网络概念；Linux 路线能提供部分背景，Windows 与 macOS 的具体机制仍需分别学习。

这里有两篇容易混淆的 Roadmap：一篇是**技术领域地图**，另一篇是**分阶段学习计划**。中间五篇分别展开需要作出的安全设计判断。

## 怎样使用这里的视频笔记

`vibe watching` 表示文章经过 AI 辅助阅读和整理。它是一种资料整理方式，不是正确性的保证。阅读时应区分课程本身的观点、课堂代码的简化，以及整理者增加的现代实现和思考。

课程名称、讲者、对应讲次和主题，比某个可能失效的视频地址更适合长期保存。蒋炎岩《生成式软件工程》、李建忠《C++ 设计模式》和 Kent C. Dodds 对 Robert C. Martin 的访谈，各篇都保留了原课程或节目身份与所用回放版本。遇到其他尚未核实的讲者信息，不靠猜测补齐。

读到关键推导时，可以回到原讲的代码变化过程，再尝试自己复现。文章中的结论通常依赖某些前提：接口是否稳定、对象能否共享、回调是否同步、操作是否可撤销。把前提改一下，再看方案还能否成立，比只记住定义更有价值。

后续会逐步补充更精确的时间戳、思考题和复现线索；目前各篇的覆盖程度并不相同，不能假定每个结论都有逐分钟定位或配套练习。新的课程笔记也会在实际整理、核对并发布以后，再加入这份路线。
